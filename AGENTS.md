# Instructions for AI agents

This repository helps developers (and AI agents) build applications with IBM Aspera APIs.
It has an integration guide and sample code in 8 languages.

Read this file first. Then read **only** the sections of the guide that you need:
the guide is long (about 1700 lines), and its sections are independent.

## Vocabulary

Use these terms in code comments and documentation.

- **Transfer Daemon SDK**: the SDK (archive, `transferd.proto`, examples).
  **Transfer Daemon**: the component. `transferd`: the executable.
- **Transfer agent**: the software that executes a transfer: `ascp`, Transfer Daemon, Web SDK, Aspera for Desktop, Connect, Node API.
  **Client** and **Server** are the roles in a transfer: a server can be the client.
- **Faspex** means Faspex 5 (Faspex 4 is deprecated). Names like `faspex5` (samples) and `/api/v5` stay as they are.

## Rules about Aspera

These are established facts. Do not contradict them in code or documentation.

- Every transfer uses `ascp`: a client `ascp` connects to a server `ascp` (SSH or WSS for the TCP part, UDP for the data).
  Transfer Daemon SDK, `ascli`, Node API and the HTTP Gateway all start `ascp`.
- A transfer is started with a **transfer spec** (JSON). 90% of its parameters are the same in the Transfer Daemon,
  Node API, Web SDK and `ascli`. Only `ascp` itself takes command line options.
- Authorization is either SSH credentials or a token. Never send SSH credentials to a browser:
  a web application uses a token generated by its back end.
- HTTP Gateway and WebSocket sessions require a token.
- With Faspex, AoC and Shares: get the transfer spec from the application API.
  Do not generate tokens for their servers by yourself.
- Do not use `FaspManager`, `FaspManager2`, Connect SDK, HTTP Gateway SDK or Aspera for Desktop SDK: they are deprecated.
  Use the Transfer Daemon (`transferd`, gRPC) and the Web SDK.
- The Node API sometimes returns an empty JSON object instead of an error: handle this case.
- Do not read or print secrets (tokens, passwords, keys). The samples mask them in logs.

## Running a sample

The configuration file is `private/config.yaml` (template: `config/config.tmpl`). Do not commit it.
The Transfer Daemon must be downloaded first: `make sdk` at the top of the repository.

```shell
cd app/python
make list                 # names of the samples
make .tested/faspex5      # run one sample
```

`make` runs against real servers: it needs the addresses and credentials of your own test environment
in the configuration file. If they are absent, do not invent them: ask.

Set `misc.level: debug` in the configuration file to see the REST calls and the transfer spec.

## Conventions for the code in `app/`

The same sample exists in several languages, and a reader compares them.
Therefore, a change to one language is applied to all languages that have the same file or function.

- **Messages**: identical in all languages, simple, and always starting with an uppercase letter
  (log messages and errors, also in Go).
  - `info`: a few progress lines (`Getting transfer spec`, `Uploading files`).
  - `debug`: data. The REST class logs `HTTP <METHOD> <url>`, `Request body` and `Response body`.
  - Use the `log_dump(name, value)` helper to log a named value (JSON, secrets masked).
  - Display a secret only with `mask_secrets`.
- **Documentation of functions**: the same text in every language (imperative sentence, same description of
  parameters and return value), in the native format of the language:
  Python reST (`:param x:`), Ruby YARD, JS JSDoc, Go GoDoc, Java Javadoc, Rust rustdoc, C# XML doc, C++ Doxygen.
- **Add a sample**: add it in every language where it makes sense, add its name to `TEST_CASES` in the `Makefile`
  of each language, and update the table in [README.md](README.md#available-samples)
  and, if it is a new scenario, the guide.
- **Placeholders**: in documentation, templates and test data, write secrets and variable values as
  `<UPPER_CASE_WITH_UNDERSCORES>` in angle brackets, named after the kind of value
  (`<PASSWORD>`, `<TOKEN>`, `<CLIENT_SECRET>`, `<HSTS1_XFER_USER>`).
  Never write a real secret, nor a fake-looking one (`mypassword`).

## Conventions for the guide

- Edit `guide/README.md`. Do not edit `guide/README.pdf`, and edit the diagrams in `guide/images/diagrams.drawio`
  (the `.svg` files are exported from it).
- Diagrams: architecture and component diagrams are drawio tabs (see above). Sequence diagrams are Mermaid blocks
  (```` ```mermaid ````) in the Markdown file: GitHub renders them, and the PDF build renders them with Mermaid CLI
  (`mmdc`, or the command of the env var `GFM2PDF_MMDC`, e.g. `mmdc -p puppeteer.json`). Do not add a drawn sequence
  diagram or a text one (ASCII, WebSequenceDiagrams).
- Section names are used in links: when you rename a heading, search the repository for its anchor.
- Keep one idea per sentence and one sentence per line: the file is reviewed with diffs.
- The guide describes concepts and flows. The reference of each REST call is in `openapi/`: link to it, do not copy it.

## Git

- Commit on `main`, short lowercase messages. Do not push unless asked.
- Never commit `private/`, `tmp/`, or any file with a secret.
